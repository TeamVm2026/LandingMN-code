# Манифест внешних оригенов

**Кто читает:** `npm run check:links` (`scripts/check-links.ts`, предмет 4).
**Кто пишет:** человек — колонки «Зачем» и «Кто владелец». Строки добавляет и
удаляет прогон `npm run check:links -- --update-manifest` по свежей сборке.

---

## Зачем этот файл существует

Угроза T-08-04 плана 08-02: **молча появившийся сторонний хост в разметке**.
Каждый новый внешний ориген — это новый канал утечки referrer, новая точка
отказа первого экрана и новая строка будущего CSP (план 08-05). Такое
изменение не роняет ни сборку, ни тесты, ни `astro check`: разметка валидна,
страница открывается, кнопка работает. Заметить его можно только сверкой
списка — и сверка эта здесь.

Гейт сверяет манифест со сборкой **в обе стороны**: незаявленный ориген валит
CI, и **мёртвая строка манифеста валит его тоже** — список, обещающий хост,
которого в сборке уже нет, лжёт ровно так же, как ссылка в никуда.

⛔ **Прочерк в колонке «Зачем» или «Кто владелец» валит гейт.** Строка,
добавленная `--update-manifest` и не описанная человеком, — это тот же
неизвестный канал, только записанный в таблицу.

## Чего этот файл НЕ делает

⛔ **Сеть не трогается.** Гейт не запрашивает ни один внешний адрес, и это
решение, а не упущение. Полное обоснование — в шапке `scripts/check-links.ts`;
коротко: (а) чужой аптайм превращает красный CI в лотерею, (б) `t.me/<кто
угодно>` отвечает 200 и для несуществующего аккаунта, то есть на главном
классе наших внешних ссылок сетевая проверка не различает ничего.

Из этого следует прямая цена, названная вслух: **удалённый Telegram-аккаунт
или переименованный бот этим гейтом не ловятся**. Их ловит дымовая проверка
бота (`docs/ops.md` §8.5) и живой клик человека.

## Колонка «Сверка»

| Значение | Что означает |
| --- | --- |
| `строгая` | Ориген встречается в **разметке** (`dist/**/*.html`). Сверка двусторонняя: и появление нового, и исчезновение заявленного валят гейт. |
| `появление` | Ориген встречается **только внутри чанков сборки** (`_astro/*.js`, `*.css`). Сверка односторонняя: новый хост валит гейт, исчезновение — нет. Причина именно такая: чанк `providers.js` **env-условен** — при пустых `PUBLIC_GA_ID`/`PUBLIC_CLARITY_ID` сборщик вырезает его целиком, и двусторонняя сверка красила бы CI в зависимости от того, включена ли аналитика на этой машине. |

⚠️ **Набор оригенов зависит от env сборки, и это поймано измерением, а не
предположением.** Прогон CI 26.08.2026 (`7329f28`) упал на
`https://challenges.cloudflare.com`: на машине разработчика
`PUBLIC_TURNSTILE_SITEKEY` пуст и загрузчика виджета в сборке нет вовсе, а в CI
стоит тестовый ключ и загрузчик есть. Именно поэтому такие оригены помечены
`появление`, а не `строгая` — иначе гейт был бы красным попеременно то локально,
то в облаке, в зависимости от того, чей `.env.local` его запустил.

⚠️ **Собственного оригена сайта в таблице нет и быть не должно.** Гейт берёт
его из `rel="canonical"` главной страницы СБОРКИ и вычитает из множества
внешних — поэтому в день привязки боевого домена (смена `PUBLIC_SITE_URL`)
этот файл править не придётся вовсе.

## Как обновлять

```bash
npm run build
npm run check:links -- --update-manifest   # переписывает ТОЛЬКО таблицу
npm run check:links                        # обязан быть зелёным после правки
```

`--update-manifest` сохраняет уже заполненные человеком колонки для оригенов,
которые остались в сборке, и ставит прочерк новым. Прочерк валит гейт — это и
есть требование описать новый хост словами, а не молча его впустить.
